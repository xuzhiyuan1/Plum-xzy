## 4. 研究主题分布【元数据 N=664 研究候选】
覆盖 edge/cache、security、scheduling、cellular/mobile、routing/SDN、energy、transport/CC、datacenter、measurement、video/QoE、wireless/Wi-Fi 与 wireless/PHY 等主题。上一版给出的“ML/AI 约 39%”没有保留可复核的聚类统计，现撤回该百分比。

## 16. trace/仿真/真实设备组合【N=2 全文 + Plum 已有】
NeuroBA: trace-driven + real-world；5G-RAN-QUIC: 5G 测试。Plum: 真实餐厅 trace + NS-3 + testbed。组合合理，须补 trace 多样性。

## 17. 系统论文 vs 纯算法论文【R1/R2 N=17】
R2 中 Pudica/Compass/BIFROST/INCC 为系统论文（有实现+部署）；QoE-Fairness/QoE-UAV-MEC 偏算法+优化。Plum 属系统论文（entangled state machine + 不侵入 MAC），需保持系统实现深度。

## 18. 会议→TON 扩展通常新增内容【综合推断】
更深理论 + 更大实验规模（N/trace/seed/baseline）+ 新维度 + testbed 强化 + Related Work 扩广度。Plum 的预测+Green 正属"新维度"。

## 19. 创新强度可能不足的情况
- “使用 RL/预测”本身不构成创新；本目录中确有大量相关方法，但当前没有可靠百分比统计。
- 仅局部口径正向（model-based +17% 而 trace-driven 失效）不足以支撑期刊主张。
- Green 能耗为模型非实测 + 3 seed → 能耗主张薄弱。
- 无新增理论（扰动界未推导）→ 创新深度短板。

## 20. 对 PLUM 最直接的投稿启示
1. 用新 ISSN/期刊名定位；Related Work 用本次真实 R1/R2。
2. 创新须"机制+理论+诚实量化"，非"用预测"。
3. 必须解决 3-seed、92°C/20W、Pred+Green 联合三大短板。
4. 取得 seq312 全文后判断它是否适合作为相关工作或 baseline；不要在问题和代码接口未对齐前强行直接对比。
5. 统一叙事需 Pred+Green 联合证据；否则改方案 B（Green 主线）。
